Hermes Agent — Deployment Architecture

Hardened multi-user agentic AI platform · Azure Bastion access · per-user container isolation · 5 MCP tool servers

5-Layer Defence-in-Depth

  • • Layer 1 — Azure NSG: deny-all inbound, Bastion SSH only
  • • Layer 2 — OS: SSH hardening, UFW firewall, fail2ban, auditd
  • • Layer 3 — Docker: cap_drop ALL, read_only FS, tmpfs, mem_limit
  • • Layer 4 — LiteLLM: master key auth, hermes-net only (:4000)
  • • Layer 5 — Wrapper: sk-hermes-<hex> per user, 20 req/min, sanitise

Request Flow

  • • User → OpenWebUI (:3000) → Wrapper (:5000)
  • • Wrapper authenticates key + resolves hermes-{username} container
  • • Hermes Agent runs SKILL.md, calls MCP servers for tools
  • • Agent calls LiteLLM (:4000) for LLM inference
  • • LiteLLM routes to Claude Sonnet 4.6 on Azure AI Foundry
  • • Response streamed back: Agent → Wrapper → OpenWebUI → User

MCP Tool Servers

  • • :8081 hermes-cve-mcp — CVE / NVD vulnerability data
  • • :8082 hermes-framework-mcp — MAS-TRM, PDPA, ISO 27001 (local data)
  • • :8083 hermes-graph-mcp — Microsoft Graph (⚠ pending admin consent)
  • • :8084 hermes-gmail-mcp — Google Gmail OAuth2
  • • :8085 hermes-mailpit-mcp — On-prem SMTP simulation
  • • :8025 Mailpit web UI · seed_emails.py for test data

AI Model

  • • Claude Sonnet 4.6 — only model used by Hermes Agent
  • • Hosted on Azure AI Foundry (Anthropic endpoint)
  • • Accessed via LiteLLM proxy on hermes-net (:4000)
  • • Corporate certbundle.crt for Azure endpoint TLS
  • • Every call logged to PostgreSQL (litellm-db)
  • • AZURE_ANTHROPIC_API_BASE + AZURE_API_KEY auth
